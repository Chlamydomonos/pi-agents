# 20 — 工作流定义

> 本篇定义工作流(agent-flow)定义文件的完整契约:节点、边、条件边、循环、传递规则、终点语义。
> 前置阅读:00-总览(D4/D5/D11/D12/D17);Agent 定义见 10。

## 1. 位置与命名

```
chlamydomonos-agents/agent-flows/
├── review-loop.ts
└── single-writer.ts        # 单节点工作流 = 单 Agent 场景(D:无特殊单 Agent 路径)
```

- 全局/工作区两级、覆盖规则、jiti、允许 import,均与 Agent 文件一致(10 §1)。
- 工作流经 `name` 暴露为虚拟模型端点(30 §模型目录);**也可被其他 Agent 的 subagents 引用**(spawn 后一次完整唤醒,10 §6.1;引用图无环由装载期保证)。
- 工作流之间**不直接互相引用**(节点只能引 Agent;组合靠 subagent 引用)。

## 2. 模块契约

最小骨架(线性两节点):

```ts
// review-loop.ts
import type { FlowDefinition } from '@chlamydomonos/pi-agents';

export default {
    name: 'review-loop',
    title: '评审循环',
    description: '写代码 → 评审;评审不通过则带意见重写,最多 5 轮',

    // 节点:引用 Agent name + 该节点特有配置
    nodes: {
        writer: { agent: 'coder', sessionMode: 'inherit' },
        checker: { agent: 'reviewer', sessionMode: 'fresh' },
    },

    // 入口节点(唯一)
    entry: 'writer',

    // 出边表:每个节点声明到哪去(见 §3)
    edges: {
        writer: 'checker',
        checker: {
            // 条件边:返回下一个节点名或 "done"(D4/D5)
            route: (out, ctx) => (/LGTM/.test(out.text) ? 'done' : 'writer'),
            maxIterations: 5, // 兜底:writer 被进入超过 5 次强制结束
        },
    },
} satisfies FlowDefinition;
```

### 2.1 字段总表

| 字段           | 类型                                             | 必需 | 说明                                                                                       |
| -------------- | ------------------------------------------------ | ---- | ------------------------------------------------------------------------------------------ |
| `name`         | string                                           | 是   | 虚拟模型 id 用它:`pi-workflows/<name>`;`[a-z][a-z0-9-]{0,63}`                              |
| `title`        | string                                           | 是   | `/model` 列表显示名                                                                        |
| `description`  | string                                           | 是   | 一句话说明;进入 `/model` 列表与模型声明                                                    |
| `nodes`        | `Record<string, NodeSpec>`                       | 是   | ≥1 个节点;键 = 节点名(工作流内唯一,`[A-Za-z][A-Za-z0-9_-]{0,63}`;允许驼峰如 `parseReview`) |
| `entry`        | string                                           | 是   | 入口节点名,必须存在于 nodes                                                                |
| `edges`        | `Record<string, EdgeSpec>`                       | 是   | 每个节点的出边声明(终点节点可缺省键,§4)                                                    |
| `pass`         | PassSpec \| PassResolver                         | 否   | 上游 → 下游的传递规则(§5);缺省 = 上游最终 assistant 文本作为下游用户消息;图片转发见 §8.3   |
| `lorebook`     | LorebookSpec                                     | 否   | **工作流级世界书**:本工作流全部节点子会话注入(与 Agent 级/工作区级自动合并,10 §5.2)        |
| `initialInput` | (wake: WakeContext) => string \| Promise<string> | 否   | 首节点输入的加工(§5.3);缺省 = 宿主本次唤醒的用户输入文本                                   |
| `meta`         | unknown                                          | 否   | 作者自定义数据,透传到各回调 ctx.flow.extra                                                 |

### 2.2 NodeSpec(Agent 节点与函数节点)

节点二选一:**Agent 节点**(有 `agent`)或**纯函数节点**(有 `run`)。

```ts
interface NodeSpec {
    /** Agent 节点:引用的 Agent name(装载期检查存在) */
    agent?: string;

    /** 函数节点:纯 TypeScript 处理函数(与 agent 二选一,见下) */
    run?: (input: FuncNodeInput, ctx: FuncNodeContext) => string | NodeOutputData | Promise<string | NodeOutputData>;

    /** 本节点会话模式(**会话模式只在此处定义**,Agent 定义不含此字段);缺省 fresh,D11;仅 Agent 节点有效 */
    sessionMode?: 'fresh' | 'inherit';
    /** 本节点模型覆盖,`"provider/id"` 格式;解析链见 10 §3.1(节点 > Agent > 配置 > pi 默认);仅 Agent 节点有效 */
    model?: string;
    /** 本节点思考级别覆盖;解析链同上;仅 Agent 节点有效 */
    thinkingLevel?: 'off' | 'minimal' | 'low' | 'medium' | 'high' | 'xhigh';
    /** 覆盖/追加系统提示词(仅本节点身份;不污染 Agent 其他使用处);仅 Agent 节点有效 */
    appendSystemPrompt?: string;
    /** 节点标签,占位工具调用与 /agent-usage 中显示;缺省 = 节点名 */
    label?: string;
    /**
     * 节点输出是否可见(流映射,30 §3.1);缺省 true;仅 Agent 节点有效。
     * true:输出先按 text 流式,收口纠偏——非终点(边界批/落定批)降为 thinking。
     * false:全部输出始终走 thinking;若为本工作流终点,直到输出彻底结束才一次性
     * 产生最终文本(不逐字流出)。
     */
    outputVisible?: boolean;
}

/** 函数节点入参 */
interface FuncNodeInput {
    /** 上游交给本节点的内容(pass 加工后的文本;入口节点 = initialInput 结果) */
    text: string;
    /** 上游结构化数据(pass.transform 的 data 通道;无则 undefined) */
    data?: unknown;
}

interface FuncNodeContext {
    visit: number; // 本节点本次唤醒内第几次执行
    wake: WakeContext;
    scratch: Record<string, unknown>; // 与 route/transform 共享的便签桶
    extra: unknown; // 节点所在 flow 的 meta + 节点自定义
    /** 工作区文件助手(§8.5;图片进入流的主要入口,pi-comfyui 兼容) */
    files: FuncFileHelpers;
    /** 宿主会话只读视图(完整对话列表;§2.2.1) */
    host: HostSessionView;
}

/** 宿主会话消息的只读投影(形状同构 pi-ai,按 type 窄化;投影已去 system) */
type HostRole = 'user' | 'assistant' | 'toolResult';

/** 文本块(同构 pi-ai TextContent) */
interface HostTextBlock {
    type: 'text';
    text: string;
}

/** 思维链块(同构 pi-ai ThinkingContent) */
interface HostThinkingBlock {
    type: 'thinking';
    thinking: string;
}

/** 图片块(同构 pi-ai ImageContent;base64 原样保留可直接消费) */
interface HostImageBlock {
    type: 'image';
    data: string;
    mimeType: string;
}

/** 工具调用块(同构 pi-ai ToolCall) */
interface HostToolCallBlock {
    type: 'toolCall';
    id: string;
    name: string;
    arguments: Record<string, unknown>;
}

/** 宿主消息内容块联合 */
type HostContentBlock = HostTextBlock | HostThinkingBlock | HostImageBlock | HostToolCallBlock;

interface HostMessageLike {
    role: HostRole;
    /** 字符串或内容块数组;toolResult 恒为数组(TextContent | ImageContent) */
    content: string | HostContentBlock[];
}

/** 宿主会话只读视图(函数节点 ctx.host;§2.2.1) */
interface HostSessionView {
    sessionId: string; // 宿主 session id(= wake.hostSessionId)
    wakeIndex: number; // 本次唤醒序号(= wake.wakeIndex,从 1 起)
    lastInput: string; // 本次唤醒输入(= wake.input)
    lastOutput?: string; // 上一次唤醒的工作流最终输出(首唤醒无则 undefined)
    /**
     * 宿主会话完整消息列表(时间序,含本唤醒前的全部历史)。
     * 不含本次唤醒尚未落盘的引擎输出;只读投影(修改无效),仅保留 role/content 等必要字段。
     */
    messages: readonly HostMessageLike[];
}

/** 函数节点返回:string = 最终文本(等价 {text});对象可带结构化 data 与图片 */
interface NodeOutputData {
    text: string; // 最终文本(进 trail/route 的 out.text;若为终点即工作流输出)
    data?: unknown; // 结构化产出(下游 pass/route 可消费)
    /** 本节点产出的图片块(D21;Agent 节点不产出图片,仅函数节点;上限见 §8.2) */
    images?: ImageContent[]; // { type:'image', data: base64, mimeType } — pi-ai 类型
}

/** 工作区文件助手(受限;禁止 `..` 逃逸工作区,超限抛错 → 工作流 error 流) */
interface FuncFileHelpers {
    /** 读图片为 ImageContent(mime 嗅探:png/jpeg/gif/webp;超过单图上限抛错) */
    readImage(relPath: string): Promise<ImageContent>;
    /** 读文本文件(UTF-8;超过 1MiB 抛错) */
    readText(relPath: string): Promise<string>;
    /** 列目录(相对路径;返回工作区内相对路径列表,目录不存在返回 []) */
    list(relDir: string): Promise<string[]>;
}
```

**函数节点语义**:

- 无子会话、无 LLM 调用:在扩展进程内直接执行,产出即 `NodeOutput`(text/data/images)。适合格式转换、JSON 解析、拼接上下文、读取工作区图片(pi-comfyui 产物)、外部脚本调用等确定性步骤。
- **宿主会话视图**(ctx.host,§2.2.1):函数节点可读取宿主完整对话历史与唤醒摘要,用于按历史分派、上下文提取、审计等。
- **图片产出**(D21):`run` 返回 `{text, images}` 即产出图片块;图片不进 prompt、不进思维链,只随 NodeOutput 流动(pass 转发/终点嵌图消费)。引擎为每个 `readImage` 记录来源工作区相对路径(内部 `imagesSrc` 字段,作者无需关心),终点嵌图(§8.4)用它生成相对路径 markdown。超过单节点产出上限(§8.2)→ 工作流 error 流。
- 透传:函数节点的 text 若出现在通往终点的路径上,**不**进思维链(它不是 LLM 输出);thinking 流仅记一行状态(`—— 函数节点 X ——`,verbose 关闭时也显示,因为它无其他可见痕迹)。
- 函数节点不产生 usage;不进 `/agent-usage` 的模型用量,但 trail 中有记录。
- `run` 抛错/返回非字符串非对象 → 工作流 error 流(原始错误消息)。
- 函数节点忽略 sessionMode/model/thinkingLevel/appendSystemPrompt/outputVisible(写了 → 装载 warning)。

#### 2.2.1 宿主会话视图(ctx.host)

- 函数节点 ctx 增加 `host: HostSessionView`:宿主 session 的**只读投影**,包括完整消息列表 `messages` 与摘要字段(`sessionId`/`wakeIndex`/`lastInput`/`lastOutput`)。
- `messages` = 宿主会话时间序全量消息(与本工作流无关的轮次同样在内;这正是"完整对话列表"的语义)。**不含本次唤醒尚未落盘的引擎输出**——工作流自身的本轮过程在 trail 里(ctx 不可直接读 trail,但 FlowRunContext 有投影,§6)。
- 只读投影:形状同构 pi-ai 消息,仅保留 `role`/`content`(`content` 为字符串或具体内容块数组,按 `type` 窄化:text/thinking/image/toolCall);修改投影对象无效也不抛错。宿主 custom 消息等异常形态由引擎归一化(块数组只保留已知形状;字符串/数组之外的形态压成单 text 块,不丢内容),作者侧无需防御。
- system 消息不进入投影(宿主投影已去 system);`role` 只会是 `'user' | 'assistant' | 'toolResult'`。
- 图片块:宿主历史消息里的图片 content 块**原样保留**在投影里(base64 可直接消费);`wake.images` 仅是本次唤醒的附件图,历史图片要用 ctx.host.messages 自取。
- 边界:subagent/subflow 内部的函数节点,其 `ctx.host` = **该子流自己的唤醒视图**(宿主 = 调用它的那个节点会话;`messages` 只含宿主传入的 task 文本,§9.8),不会泄漏外层宿主完整历史。
- 示例:把宿主最后一条 user 消息之外的历史拼进下游提示:
    ```ts
    run: (_input, ctx) => {
        const past = ctx.host.messages
            .filter((m) => m.role === 'user')
            .map((m) => String(typeof m.content === 'string' ? m.content : '[块消息]'));
        return `用户历史提问(共 ${past.length} 条):\n${past.join('\n')}`;
    };
    ```

**Agent 节点约束**:

- 同一 Agent 可被多个节点引用(不同 sessionMode/appendSystemPrompt/model 即不同实例);子会话池按 `(flow, hostSession, node)` 键隔离(40 §3)。
- `model`/`thinkingLevel` 仅覆盖**本节点的子会话**;同一 Agent 的其他节点/其他工作流引用不受影响。
- `agent` 引用悬空 → 工作流整体判无效(warning 列出缺失名)。

### 2.3 校验规则

装载器校验(不过 → 该工作流不注册为模型,warning 带原因):

- default 导出对象;name/title/description 非空且 name 匹配模式;nodes 非空;entry ∈ nodes;节点名匹配 `[A-Za-z][A-Za-z0-9_-]{0,63}`(**允许大写驼峰**,如 `parseReview`;含 `-`/`_`)。
- 每个节点 `agent` 与 `run` **恰好一个**(都缺/都有 → 判无效);agent 为字符串;run 为函数。
- edges 键 ⊆ nodes;边目标(静态字符串或 route 函数返回值校验,见 §3.3)∈ nodes ∪ {"done"}。
- `route` 为函数;`maxIterations` 为正整数;`targets`(D24 纯展示字段)为字符串数组,每项 ∈ nodes ∪ {"done"}(**装载校验成员合法性**——错拼的展示线会误导面板图;不校验 route 实际会走哪条)。
- 函数节点返回对象时 `text` 必须为字符串;`images` 存在时必须是数组且每项为合法 ImageContent 形状(`{type:'image', data:string, mimeType:string}`)——**装载期只校验类型签名**(`run` 未执行),运行期产出再按 §8.2 上限校验。
- `lorebook` 校验同 Agent 级(10 §2.2:entries/trigger 为函数,persistent 布尔,条目 target/slot/depth 合法)。
- 图可达性:从 entry 出发(把条件边目标都算上)应能到达"结束";**不强制**(不可达节点仅 warning;全环且 route 永不返回 done 靠 maxIterations 兜底)。
- 不做并行/多入边屏障——D5 下结构上不存在。

## 3. 边与条件边(D4/D5)

### 3.1 两种边写法

```ts
edges: {
    // ① 静态边:无条件去某节点
    writer: "checker",

    // ② 条件边对象
    checker: {
        route: (out, ctx) => /LGTM/.test(out.text) ? "done" : "writer",
        maxIterations: 5,
        // ③ targets(D24):声明 route 的**候选**目标,仅供 pi-web 运行图画候选分支线;
        //    纯展示,不影响执行;不声明则面板画通用 "?" 路由标记
        targets: ["done", "writer"],
    },
}
```

### 3.2 route 函数签名

```ts
type RouteFn = (out: NodeOutput, ctx: RouteContext) => string | Promise<string>;
// 返回值:下一节点名 | "done"
// 返回 nodes 中不存在的名字或非法值 → 视为运行期错误(D17:工作流 error 流)

interface NodeOutput {
    /** 该节点最终文本:Agent 节点 = 最终 assistant 文本(getLastAssistantText);函数节点 = run 返回的 text */
    text: string;
    /** Agent 节点:最终 assistant 消息完整结构(文本/思维链/工具调用块);函数节点 = undefined */
    message?: AssistantMessage;
    /** 本轮该节点的结构化产出:Agent 节点 = pass.transform 返回值(§5.2);函数节点 = run 返回的 data;均无则 undefined */
    data?: unknown;
    /** 该节点本轮执行统计(durationMs, llmRequests, toolCalls, usage;函数节点 llmRequests/toolCalls/usage 恒为 0) */
    stats: NodeRunStats;
}

interface RouteContext {
    /** 该节点本轮是第几次被执行(该唤醒内;循环判定主要靠它) */
    visit: number;
    /** 唤醒上下文(宿主输入、宿主消息 id 等,§5.3) */
    wake: WakeContext;
    /** 跨节点/跨轮共享的便签桶(仅本次唤醒存活;结构随意) */
    scratch: Record<string, unknown>;
    /** 工作流 meta 与节点 meta */
    extra: unknown;
}
```

### 3.3 route 语义细则

- 每次节点执行完成后调用一次;返回值决定下一站。**返回 "done" = 工作流结束,本节点即终点节点**。
- `maxIterations`:对**声明它的那条边的目标节点**生效——目标节点在本唤醒内被执行次数超过 N 时,不再执行,直接结束(等价 route 强制返回 "done")。日志 warning 说明触发位置。放在边上而非全局,是因为同一节点可能被多条边进入、语义不同。
- 静态边等价 `route: () => target`,无 maxIterations(想限环就写条件边)。
- **if 分叉**(D5):route 返回不同节点名即是分叉;一次执行只走一条,无并行。想要"两路都要跑",用串联节点或把另一个 Agent 做成本节点的 subagent。
- `targets`(D24):条件边的**展示用**候选目标列表;执行完全由 route 决定,targets 与实际走向不一致**不报错**(面板只画静态候选线,真实走向靠运行图点亮);省略时 pi-web 对该条件边画通用 "?" 标记。静态边无需 targets。
- route 抛错 / Promise reject → 工作流 error 流(带原始错误消息,便于作者调试;同 pi-comfyui 生成器哲学:错误原样到达用户)。

## 4. 终点(D17)

- 节点 `n` 是终点,当:edges 无 `n` 键,或其 route 返回 `"done"`。
- **工作流输出 = 终点节点的最终 assistant 文本**;它成为虚拟模型流上最终的 text 内容(30 §3)。
- 设计建议(写进 50 指南):终点节点最好是无工具的"总结者"Agent(fresh、无 subagents),保证输出干净;直接以带工具的节点为终点也合法(输出=其最后一条文本)。

## 5. 传递规则(pass)

默认行为:**上游节点的最终 assistant 文本,作为下游节点的用户消息**(需求原文)。`pass` 用于改默认。

### 5.1 PassSpec

```ts
type PassSpec =
    | { mode: 'text' } // 缺省:最终文本 → 下游 user 消息
    | { mode: 'none' } // 不传内容;下游 user 消息 = 提示语"继续你的任务"
    | { mode: 'template'; template: string } // 模板插值(§5.4)
    | { mode: 'custom'; transform: PassTransform } // 完全自定义(§5.2)
    | { mode: 'text'; images: 'forward' }; // 文本照旧 + 附带转发上游图片(§8.3)

type PassTransform = (
    out: NodeOutput,
    ctx: PassContext,
) =>
    | string // 纯文本 → 下游 user 消息
    | { userMessage?: string; data?: unknown; images?: ImageContent[] } // userMessage 为空 = 不发新消息(仅投喂数据);images = 显式指定转发给下游的图片
    | Promise<string | { userMessage?: string; data?: unknown; images?: ImageContent[] }>;

interface PassContext {
    to: string; // 下游节点名
    visit: number; // 下游节点第几次被进入(循环场景可据此写"第 N 轮意见")
    wake: WakeContext;
    scratch: Record<string, unknown>; // 与 route 共享同一便签桶
    extra: unknown;
}
```

- `pass` 写在工作流顶层 = 全局默认;写在 `edges[t].pass` = 覆盖该条边。**pass 归属边**(它描述"从上游拿什么"),故顶层 pass 对所有静态与条件边生效。
- `data`:transform 的返回值会记录进该节点执行后的 `NodeOutput.data`,供 route 与下游 transform 链式消费(结构化协作通道,不进 prompt)。

### 5.2 语义细则

- transform 抛错 → 工作流 error 流(原始错误消息)。
- `mode: "template"` 的模板变量:`{{text}}`(上游文本)、`{{visit}}`(下游进入次数)、`{{data.<path>}}`(上游 data 取值;JSON 路径,不存在为空串)。转义:`{{{{` 原样输出。
- 模板/文本过长的裁剪策略:不做自动裁剪(作者可用 transform 自行截断);文档提示 token 经济(50 §3.6)。

### 5.3 WakeContext(唤醒上下文)

```ts
interface WakeContext {
    /** 宿主本次唤醒的用户输入(纯文本;图片附件位置为 "[图片 xN]" 占位,真实图片在 images 通道) */
    input: string;
    /** 宿主本次唤醒附带的图片块(D21;按 §8.2 上限过滤与截断后的结果;无附件 = []) */
    images: ImageContent[];
    /** 宿主 session id(用于会话池键) */
    hostSessionId: string;
    /** 本宿主 session 内第几次唤醒(从 1 起) */
    wakeIndex: number;
    /** 上一次唤醒的工作流最终输出(inherit 场景供参考;fresh 场景同样提供) */
    lastOutput?: string;
}
```

- `initialInput` 只加工**入口节点**的输入;后续节点输入一律由 pass 决定。两个回调都拿到同一 wake 对象。
- `wake.images` 只对**入口节点**的 prompt 自动生效(§8.3);route/transform/run/initialInput 也可读它做自定义处理(如把图片转存工作区)。

### 5.4 循环中的传递示例

edges: {

## 6. 运行上下文(LorebookContext.flow / RouteContext 引用的 FlowRunContext)

```ts
interface FlowRunContext {
    flow: { name: string; title: string; meta: unknown };
    currentNode: string;
    visit: number; // 当前节点本次唤醒内的执行序号
    wake: WakeContext;
    /** 已完成节点的输出轨迹(按执行顺序;含 text 与 data) */
    trail: Array<{ node: string; visit: number; text: string; data?: unknown }>;
}
```

- 世界书 trigger(10 §5)读 `ctx.flow.trail` 即可实现"根据上游说了什么决定注入什么";工作流级世界书(LorebookContext.agent 仍是当前节点 Agent 名)可按节点分支筛选。
- 函数节点 `run` 的 ctx(FnNodeContext)是 FlowRunContext 的投影(text/data 输入 + visit/wake/scratch/extra);trail 亦可在 run 里读(20 §2.2)。
- 只读;修改 scratch 请走 route/transform/run 的 ctx。

## 8. 完整示例:三节点带环 + 汇总终点

```ts
import type { FlowDefinition } from '@chlamydomonos/pi-agents';

export default {
    name: 'dev-loop',
    title: '开发循环',
    description: '规划 → 实现 → 评审;通过则汇总,否则带意见回到实现(≤4 轮)',
    nodes: {
        plan: { agent: 'planner', sessionMode: 'inherit', label: '规划' },
        code: { agent: 'coder', sessionMode: 'inherit', label: '实现' },
        review: { agent: 'reviewer', sessionMode: 'fresh', label: '评审' },
        // 函数节点:从评审输出中解析结构化意见,供模板边引用
        parseReview: {
            run: (input) => {
                try {
                    return { text: input.text, data: JSON.parse(input.text.match(/\{[\s\S]*\}/)?.[0] ?? '{}') };
                } catch {
                    return { text: input.text, data: null };
                }
            },
        },
        wrap: { agent: 'summarizer', sessionMode: 'fresh', label: '总结' },
    },
    entry: 'plan',
    edges: {
        plan: 'code',
        code: 'review',
        review: 'parseReview',
        parseReview: {
            route: (out) => (out.text.includes('LGTM') ? 'wrap' : 'code'),
            maxIterations: 4, // 约束的是目标节点 code
            targets: ['wrap', 'code'], // D24:运行图候选分支
            pass: { mode: 'template', template: '评审未通过(第 {{visit}} 轮),意见如下:\n{{text}}\n\n请修改。' },
        },
    },
} satisfies FlowDefinition;
// wrap 无出边 = 终点;其最终文本 = dev-loop 的输出
```

## 9. 图片通道(D21/D22)

> 目标:用户附图进工作流、节点产出图片接力、终点在 **pi-web 聊天中可见**。TUI 显示图片为**非目标**;subagent/subflow 唤醒不传图。

### 9.1 形态模型

```ts
// NodeOutput(引擎内部;由 NodeOutputData/Agent 节点产出归一化而来)
interface NodeOutput {
    text: string;
    data?: unknown;
    stats: NodeRunStats;
    /** 本节点产出的图片(函数节点 run 返回;Agent 节点恒空,见 §9.6) */
    images?: NodeImage[];
}

interface NodeImage {
    image: ImageContent; // {type:'image', data(base64), mimeType}
    /** 来源工作区相对路径(经 ctx.files.readImage 读取时自动记录;终点嵌图与降级清单都用它) */
    src?: string; // 如 "comfyui-output/sunset.png"
}
```

- 图片是 NodeOutput 的旁路通道:不进 prompt 文本、不进思维链、不进 trail 文本;trail 条目仅记 `images: N`(计数,不带数据)。
- WakeContext.images(§5.3)= 宿主唤醒图片,同样旁路。

### 9.2 上限(D21,可配,40 §11)

| 上限            | 缺省 | 触发行为                                                     |
| --------------- | ---- | ------------------------------------------------------------ |
| `maxWakeImages` | 4    | 宿主唤醒附图超出 → 多余的丢弃 + thinking 行提示              |
| `maxImageBytes` | 2MiB | 单图 base64 解码前超限 → 丢弃 + thinking 行提示(不报错,继续) |
| `maxNodeImages` | 8    | 单节点 images 产出超出 → 工作流 error 流(作者错误,明确报)    |

- 配置于 `config.json`(40 §11 图片组);0 = 全部禁止(该通道关闭,函数节点返回 images → error)。

### 9.3 用户 → 入口节点

- `streamSimple` 提取唤醒输入时(40 §4.1),从末条 user 消息收集 ImageContent 块 → WakeContext.images(按 §9.2 过滤);input 文本中保留 `[图片 xN]` 占位(感知用)。
- **仅入口节点**的 `session.prompt(initialInput, { images: wake.images })` 自动附带图片;后续节点不自动获得(防 token 膨胀)。
- 需要接力时用 pass 显式转发(§9.4),或入口前放函数节点把图片转存工作区(§9.5)。

### 9.4 节点 → 节点(pass 显式转发)

- `{ mode: 'text', images: 'forward' }`:上游 NodeOutput.images 原样附到下游 prompt(上限 maxNodeImages 内)。
- `transform` 返回 `{ userMessage, images }`:显式指定(可从上游 images 挑选/改造,如丢弃 data 大块);返回不含 images 键 = 不转发。
- **缺省(任何 mode)不转发图片**——既有工作流行为不变。

### 9.5 函数节点读工作区图片(ctx.files,§2.2 FuncFileHelpers)

- `ctx.files.readImage(relPath)`:路径安全(解析后必须仍在工作区内,`..` 逃逸 → 抛错)、mime 嗅探(png/jpeg/gif/webp)、超 maxImageBytes 抛错;**返回的图片自动携带 `src` 相对路径**。
- `readText`/`list` 同样受限;list 便于 `comfyui-output/` 枚举挑产物(配合 pi-comfyui:生成器落盘 → 函数节点 list+readImage)。
- 子会话与宿主共享 cwd,文件工具(read/bash)本来就能触达这些文件;ctx.files 的价值 = **拿到 ImageContent 形态 + 自动记录 src**,供终点嵌图。

### 9.6 Agent 节点不产出图片(边界)

- `AssistantMessage.content` 只有 Text/Thinking/ToolCall 三种块(已核实 pi-ai 类型),**Agent 节点的最终消息没有图片块**。
- Agent 想把图带进流:调工具(comfyui_generate 等)落盘 → 下游函数节点 `ctx.files.readImage` 读入;或 Agent 在文本里写 markdown 路径引用(但无 src 记录,嵌图可靠性差,不作为机制依赖)。

### 9.7 终点嵌图(D22:markdown 相对路径引用)

- 终点节点(或最后到达节点)的 NodeOutput.images 非空时,收尾流程(40 §4.3):
    1. 逐张检查 `src`:有 src → 生成 `![工作流图片](<src>)` 行;无 src 的图片(理论上仅来自 transform 显式构造,无路径)→ 跳过并在 thinking 行提示。
    2. 全部图片行按顺序追加到终点文本后(空行分隔),再走虚拟流 text 通道。
    3. 配置 `embedFinalImages: 'markdown' | 'off'`(缺省 'markdown');'off' 时图片仅留在 trail/调试,不出现在输出文本。
- **已核实的渲染依据**(pi-web 源码,2026-10-13):聊天 Markdown 的 `![alt](相对路径)` 经 `replaceLocalMarkdownImages` 转成 workspace preview URL 渲染(懒加载/点击放大);`data:` URI 被 sanitizer 剥离、裸 HTML `<img>` 被转义——所以**只支持工作区相对路径**的 markdown 引用,base64 data URI 通道不存在。
- TUI 不渲染 markdown 图(显示为普通文本行);接受(非目标)。

### 9.8 与 subagent/subflow 的边界(D21)

- spawn\_\* 工具参数保持 task/context 纯文本;WakeContext.images/NodeOutput.images 不跨越 spawn 边界(subflow 唤醒的输入 = task 文本)。
- subflow 内需要图:由宿主侧函数节点先把图落到工作区文件,subflow 内函数节点 ctx.files 再读。

### 9.9 示例:pi-comfyui 生成 → 读图 → 嵌图

```ts
// agent-flows/gen-review.ts
import type { FlowDefinition } from '@chlamydomonos/pi-agents';

export default {
    name: 'gen-review',
    title: '生成并评审',
    description: '生成图片 → 读图嵌入 → 让评审 Agent 看图说话',
    nodes: {
        gen: { agent: 'img-generator' }, // Agent,带 comfyui_generate 工具;图片落盘 comfyui-output/
        collect: {
            run: async (input, ctx) => {
                // 从生成器输出的路径清单里挑最新一张
                const files = await ctx.files.list('comfyui-output');
                const last = files.filter((f) => f.endsWith('.png')).at(-1);
                if (!last) return { text: input.text, data: { found: false } };
                const img = await ctx.files.readImage(last); // 自动带 src
                return { text: input.text, images: [img.image], data: { found: true, path: last } };
            },
        },
        review: { agent: 'img-reviewer' }, // 看图评审(模型需支持 image 输入)
        polish: { agent: 'polisher' }, // 终点:汇总评审
    },
    entry: 'gen',
    edges: {
        gen: 'collect',
        collect: { route: (out) => (out.data?.found ? 'review' : 'polish'), targets: ['review', 'polish'] },
        // review → polish:显式转发图片(评审收到的 user 消息带图)
        review: { route: () => 'polish', pass: { mode: 'text', images: 'forward' } },
    },
} satisfies FlowDefinition;
// collect 的图片 → review(看图)→ polish(pass 转发 → 终点嵌图,pi-web 聊天可见)
```
