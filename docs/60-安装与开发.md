## 2. 依赖模型

```jsonc

{
    "name": "@chlamydomonos/pi-agents",
    "keywords": ["pi-package"],

    "pi": { "extensions": ["./src/extension/index.ts"] },
    "exports": { ".": "./src/extension/types.ts" }, // 作者 import type { AgentDefinition } from "@chlamydomonos/pi-agents"
    "dependencies": { "jiti": "^2" },
    "peerDependencies": {
        "@earendil-works/pi-coding-agent": "*",
        "@earendil-works/pi-ai": "*",

        "typebox": "*",
    },
    "dependencies": { "jiti": "^2", "lit": "^3" }, // lit:浏览器面板 UI(打进 bundle)

```

- **jiti**:唯一运行时依赖(装载用户 TS)。
- typebox:占位工具/subagent 工具的参数 schema(pi 宿主提供,同 pi-comfyui 做法)。
- `exports` 指向 `types.ts`(纯类型)——作者文件里 `import type` 不产生运行时依赖;扩展同时注册一个无路径解析的模块别名兜底(jiti alias `pi-agents` → types.ts),保证没装本包的工作区也能类型擦除通过。
    - 实现注意:作者文件 import "pi-agents" 若解析失败,jiti alias 必须生效;装载器在 alias 后仍失败 → 判无效并提示。

## 3. 构建/检查

- **扩展运行时免构建**(pi jiti 直载 TS);`npm run typecheck`(tsc --noEmit)保证仓库自身类型正确。
- **pi-web 插件必须构建**(宿主不编译插件源码,70 §1):

```jsonc
// package.json scripts
{
    "build:plugin": "node esbuild.config.mjs",
    "watch:plugin": "node esbuild.config.mjs --watch",
    "typecheck": "tsc --noEmit",
}
```

- esbuild 配置要点:两个入口(`src/plugin/browser/index.ts`、`src/plugin/server/index.ts`),`--bundle --format=esm --external:@jmfederico/pi-web`(宿主运行时提供,peer),lit 打进 bundle;产物落 `dist/plugin/{browser,server}/`;**browserRoot = dist/plugin/browser** 只放运行时物(无 sourcemap,控包体 ≤16MiB)。
- `dist/` 只在安装为 pi-web 插件时需要;纯扩展使用(`pi --extension …`)无需构建。

## 6. 实现顺序建议(里程碑)

1. **M1 骨架**:types + loader(scan/load/validate)+ 配置;装载 examples 并打 warning/表。
2. **M2 引擎(假执行器)**:runner/pass/route/maxIterations + 函数节点(runFnNode);单元测试绿。
3. **M3 子会话**:pool/spawn/seed + 真实 LLM 跑通单节点工作流(notes 示例)。
4. **M4 虚拟模型**:provider/stream 映射/占位工具/激活控制;dev-loop 跑通。
5. **M5 世界书**:三级来源合并/注入器(depth + system 槽位)+ 示例(含 lorebooks/house-style)。
6. **M6 subagent**:spawn\_\* 工具/递归/inherit + 工作流引用(subflow 唤醒、引用图查环)。
7. **M7 记账与命令**:usage acc + /agent-usage;resume/中断打磨;手工验收清单全绿。
8. **M8 图片通道**:wake.images 提取/passImages/embedFinalImages/ctx.files(20 §9);单元测试 + 嵌图端到端。
9. **M9 pi-web 插件**:protocol/emit(扩展侧)→ 服务端桥接/快照 → 浏览器面板(目录区 + 运行图);按 70 §7 验收。

## 7. 开发约定

- 错误哲学(承 pi-comfyui):**用户代码的错误原样透传**(route/transform/trigger 抛错带原始消息进 error 流或 warning),扩展自身的错误带上下文前缀(`[pi-agents]`)。
- 所有状态清理幂等(`session_shutdown` 可被多次触发)。
- 日志:`console.warn/debug` 前缀 `[pi-agents]`;不打印用户 prompt 内容(信任模型内含隐私,少留痕)。
- 文档与实现偏差:改文档为准、实现跟随(同 pi-comfyui 的冲突处理规则);每次偏差在本篇追加「实现偏离」小节记录。

## 8. 实现偏离(真实环境验收记录,pi v1.1.0)

以下事实在真实 LLM 环境验收(本地 qwen3.8-27b 端点)中发现并已按 pi 实际行为适配,单测同步覆盖:

1. **Provider 注册必须在扩展工厂体内完成**。pi v1.1.0 中 `resourceLoader.reload()`(loading 态)执行扩展工厂,`pi.registerProvider` 进入 pending 队列,并在 `createAgentSessionServices` 里于 **CLI `--model` 解析之前** flush。若延后到 `session_start` 事件再注册,`--model pi-workflows/<flow>` 会报 Model not found(且 `--list-models` 看不到)。因此工厂尾部做一次预装载(`scanAndRegister(process.cwd(), false)`),`session_start` 再全量重扫刷新。
2. **done 消息严禁携带占位 toolCall 块**。宿主 agent-loop 会把最终 assistant 消息 content 里的 toolCall 当作真实工具调用执行并续跑(reason: "continuation"),曾造成整条工作流无限循环重唤醒。`buildFinalContent` 只保留 thinking + text;流式期间的 toolcall 透传(toolcall_start/delta/end)不受影响。
3. ~~WakeArgs 顶层 `seedInputOf` 转发契约~~:inherit 首唤醒宿主历史导入功能已整体移除(2026-10-15)——该功能用 `session.prompt(digest)` 注入摘要,实际触发一整轮真实 LLM 请求(摘要被模型当作待回应输入回答;若测试 Agent 要求调 ask_user 还会产生不可见的幽灵提问)。inherit 语义改为:首唤醒 = 空会话直接执行本次输入,跨唤醒记忆只靠池内 session 复用。原防回归测试随功能删除。
4. **子会话模型默认漂移**:子会话模型解析链(spec.model > agent.model > 工作区 `config.json` 的 `model`)全空时,SDK 用自身 settings 默认模型——**不是宿主 CLI 选的模型**(实测会静默调用 pi 全局默认)。真实环境验收须在工作区 `.pi/chlamydomonos-agents/config.json` 显式配置 `model`(可用 `/agent-init` 建目录后手写),否则子会话会调用非预期模型。
