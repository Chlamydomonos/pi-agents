## 1. 扩展生命周期

```ts
export default function (pi: ExtensionAPI) {
    // 工厂内(允许,queued until runner binds):
    //   1. 扫描+装载 agents/flows(同步 jiti,可能较慢——首启动可接受;/reload 同样走这)
    //   2. 注册 subagent 无关的固定件:agents_tool 占位工具、/agent-usage 命令、
    //      context 事件钩子(宿主历史瘦身,§9)、model_select 钩子
    //   3. registerProvider("pi-workflows", …) —— flows 全失败则跳过
    pi.on('session_start', (event, ctx) => {
        /* 会话池初始化/恢复(§7) */
    });
    pi.on('session_shutdown', () => {
        /* 幂等清理(§8) */
    });
}
```

- 遵守 pi 生命周期铁律:工厂内不启进程/套接字/定时器;子会话全部惰性创建(首次唤醒时),`session_shutdown` 清理。
- `session_start.reason`:startup/reload → 空池;new → 空池;resume/fork → 按 §9 恢复。

## 2. 装载与缓存

### 2.1 扫描

- 两级目录并集:全局 `~/.pi/agent/chlamydomonos-agents/{agents,agent-flows,lorebooks}` + 工作区 `<cwd>/.pi/chlamydomonos-agents/{agents,agent-flows,lorebooks}`。lorebooks/ 为工作区级世界书(10 §5),对所有子会话自动生效;同名(相对路径)工作区覆盖全局。
- `.ts`/`.js` 单文件,或含 `index.ts`/`index.js` 的目录(一层);不递归其他深度。
- 顺序:先全局后工作区;后装载者 name 相同 → 覆盖(记录 debug 行)。

### 2.2 装载(jiti)

- jiti 实例带缓存;模块级 mtime 检查:每次**使用前**(工作流被唤醒 / subagent 被调用 / 注册 provider 时)stat 全部已装载文件,mtime 变化 → 单文件重装(jiti 可按路径失效)。
- 重装失败的文件:保留**旧定义**继续用,warning(与 pi-comfyui 生成器"校验不过即无效"不同——Agent 系统更强调可用性;但**首次**装载失败 = 无旧版 = 判无效)。
- 顶层 `import` 允许(D3);校验规则见 10 §2.2 / 20 §2.3。

### 2.3 引用解析次序

1. 全量装载所有 Agent 与工作流文件 → 两张名字表(subagents 引用的 name 先查 Agent 表再查工作流表;同名 → Agent 优先 + warning)。
2. 解析工作流 nodes 引用:agent 节点悬空 → 该工作流无效;节点 agent/run 均缺或均有 → 无效(20 §2.3)。
3. 解析 subagents 引用(悬空 → 条目忽略 + warning)。
4. **引用图查环**:节点(Agent 类型)→ Agent 边、Agent → subagent 边、subagent → 工作流 边,合一张有向图 DFS;环上所有成员(含经过的工作流/Agent)判无效,每个成员一条 warning;工作流自引用同样拒绝。无环通过后各对象生效。
5. 注册 provider(有效 flows)。

## 3. 会话池(核心状态)

```ts
// 键空间(全部在内存;不跨进程)
interface SessionPool {
    // 工作流节点子会话:键 = flowName + hostSessionId + nodeName
    node: Map<string, NodeSession>;
    // subagent 子会话:键 = 父子会话键 + subagentName(仅 session:"inherit" 时入池)
    sub: Map<string, AgentSession>;
}

interface NodeSession {
    session: AgentSession; // fresh 模式:每唤醒替换;inherit:复用
    sessionManager: SessionManager; // inMemory;inherit 时跨唤醒保留
    wakeIndex: number; // 建池时的唤醒序号
}
```

### 3.1 fresh 模式(缺省)

每次唤醒:新建 `SessionManager.inMemory()` + `createAgentSession` → 执行 → **保留对象至唤醒结束即弃**(下一唤醒重建)。本唤醒内同一节点的多轮 LLM 请求自然共享 session(Agent 多轮工具循环)。

### 3.2 inherit 模式(D11/D12)

- **首唤醒(首次被进入)**:`SessionManager.inMemory()`,空会话直接执行本次唤醒输入(不导入宿主历史——宿主历史属于宿主,子会话从本次输入开始)。
- **后续唤醒**:复用池中 session;宿主本次唤醒输入作为新 user 消息追加(经 pass/initialInput 逻辑,与 fresh 相同的入口,只是 session 不同)。
- **清理时机**:宿主 session 结束(`session_shutdown`)、宿主切换分支(`/tree` 跳到不含当前尾的分叉——`session_tree` 事件重置全部 inherit 池,保守但正确)、工作流定义被重装且节点身份变化(§2.2 重装检测:agent 或 sessionMode 变了 → 该键弃用重建)。
- 上下文超限:子会话 settingsManager 关闭自动 compaction,超限时该子会话报错(工作流 error 流,提示用户该节点对话过长,建议改 fresh 或重启宿主 session)。inherit + 长循环的 token 经济是作者责任(50 §3.6)。

### 3.3 subagent 会话(D7)

- `stateless`(缺省):每次 spawn\_\* 调用新建,结束即弃。
- `inherit`:键 = 父子会话键 + subagent 名;父(fresh 节点)弃用 → 子一并清理。
- 与节点 sessionMode 无联动:节点 inherit 不代表它的 subagent inherit——各自配置。
- **工作流引用**(subflow 唤醒)不在本池:它复用目标工作流自己的节点池/引擎,但 hostSessionId 换成发起 spawn 的子会话的标识(链式键,如 `outerflow#node>sub:dev-loop`),保证外层工作流的 inherit 子会话与 subflow 唤醒互不污染(10 §6.2)。

## 4. 唤醒语义

### 4.1 唤醒输入提取(streamSimple 入口)

```
context.messages(宿主完整请求,含 system 消息)
  → 过滤 system 消息
  → 取末尾最后一条 user 消息 = 本次唤醒输入(D12)
     - 其 content 拼接文本块(图片块位置以 "[图片 xN]" 占位)
     - ImageContent 块收集为 wake.images(按 20 §9.2 上限过滤:超 maxWakeImages 丢弃尾图、
       超 maxImageBytes 丢弃单图;每次丢弃/收集后 thinking 行提示一次汇总,如 "收到 2/4 张图片(1 张超限丢弃)")
  → 更早历史留给宿主;子会话不携带宿主历史(fresh);inherit 跨唤醒记忆靠池内 session 复用
```

- 宿主 history 中若上一轮是**别的模型**产生的(用户中途切模型),无特殊处理:唤醒输入照样是最后一条 user 消息。
- 空输入(理论上不会出现)→ error 流。

### 4.2 引擎执行(单次唤醒)

```
run(flow, wake):
  scratch = {}; trail = []; counters = Map<node, n>
  node = entry; input = await initialInput?.(wake) ?? wake.input
  loop (maxHops = 64 硬上限,防 route 环无 maxIterations 时失控):
    c = counters[node]++
    if (edge.maxIterations && c > edge.maxIterations) → 终点=当前节点? 否——结束于"限次到达"
        (语义:目标节点不再执行;工作流以**最近完成节点**的输出为终点输出,thinking 行注明触发)
    if (node.run)                                   // 函数节点(20 §2.2):无池、无子会话
        output = await runFnNode(node, input, wake)   // 直接执行,产出 text/data;thinking 行记状态(无其他可见痕迹)
    else:
        session = pool.acquire(flow, node, c, hostSessionId)     // §3
        output = await runNode(node, session, input, wake)        // 子会话 prompt + 事件映射(30 §3)
    trail.push({node, visit:c, …output})
    edge = edges[node]
    if (!edge) → 终点 = node;break
    next = await edge.route(toNodeOutput(output), ctx{visit:c+1?…, scratch, wake})
    if (next === "done") → 终点 = node;break
    passSpec = edge.pass ?? flow.pass ?? {mode:"text"}
    input = await applyPass(passSpec, output, {to: next, …});   // data 通道:scratch/NodeOutput.data
    nextImages = await passImages(passSpec, output);             // §5.5:{mode:text,images:'forward'} 或 transform.images → 下一节点 prompt images
  return terminalText(trail, 终点) → embedFinalImages(终点, config)  // §5.5 收尾:图片 → markdown 行追加(20 §9.7)
```

- `maxHops` 兜底:总跳数上限(缺省 64,配置可调),防作者写错 route 永不 done 又没配 maxIterations;超限 = error 流(明确提示,区别于 maxIterations 的"温和结束")。
- 同一唤醒内**重入同一节点**(环):fresh → 全新子会话(第 N 次进入互不知情);inherit → 同一子会话,第 N 次输入自然追加(它记得上一圈)。这是"工作流每次被唤醒产生新 session / 继承上次 session"两模式的精确语义(D11 在唤醒粒度,环内重入粒度同节点模式)。

## 5. runNode 细节

1. 取 NodeSpec(appendSystemPrompt、label);组装子会话 resourceLoader(getSystemPrompt 每请求计算:systemPrompt 列表 + 三级世界书 system 条目槽位插入,10 §5.1)。
2. 世界书:子会话 inline extension 挂 context 钩子,同时评估三级来源(Agent 级 + 工作流级 + 工作区级,10 §5.2);LorebookContext.flow/agent 由引擎构造。
3. 透传监听:session.subscribe 把 thinking/text/toolcall 事件交映射器(30 §3),携带 agentPath。
4. 执行:`await session.prompt(input, {expandPromptTemplates: false, source: "pi-agents", images})`;**images** = 入口节点为 `wake.images`(20 §9.3),中间/终点节点为 pass 转发结果(§5.5,缺省空)。等待 settle。
5. 产出:`getLastAssistantText()` + 完整消息 + usage 累计(§6);**Agent 节点 images 恒空**(20 §9.6)。
6. 用户 Esc:prompt reject/aborted → 引擎捕获 → 流 aborted(30 §2.7);子会话已 dispose。
7. 函数节点(runFnNode):`await node.run({text, data}, ctx{visit, wake, scratch, extra, files, host})`;`ctx.files` = 工作区文件助手(20 §2.2/§9.5:readImage 自动记 src、路径安全、上限抛错);`ctx.host` = 宿主会话只读视图(20 §2.2.1:wakeFlow 从宿主请求消息投影 projectHostView,含完整对话列表 messages 与 sessionId/wakeIndex/lastInput/lastOutput;去 system、只保留 role/content 投影)。返回值归一化为 `NodeOutput`(string → {text});**images 产出校验**:非数组/形状非法 → error 流;超 maxNodeImages → error 流(20 §9.2)。组装 stats(durationMs 计时,llmRequests/toolCalls/usage = 0);**无池交互**。run 抛错 → error 流(原始消息);abort 时若 run 未返回,放弃其结果并按 aborted 流结束(不做强制 kill——纯函 数节点作者自担阻塞风险,50 §3.4 有提示)。

## 5.1 函数节点与子会话体系的边界

- 不 acquire 池、不创建 session、不进 §6 记账的模型用量(仅 trail 有耗时)。
- run 在扩展进程内同步/异步执行;**禁止**在 run 内再 spawn 子代理/调用虚拟模型(会形成引擎重入;类型上 ctx 不暴露任何 session 能力)。

- 子会话中的扩展命令:不存在(prompt 的扩展命令解析在宿主,子会话不加载宿主扩展;其 inline extensions 仅世界书+透传)。
- 子会话与宿主共享 cwd(文件工具操作同一工作区;文件变更对双方可见——期望行为,Agent 工具就该动真格)。

### 5.5 图片收尾与转发(20 §9 的运行时落点)

**pass 图片转发(passImages)**:

- `{mode:'text', images:'forward'}`:上游 NodeOutput.images(≤maxNodeImages)原样作为下游 prompt 的 `images` 参数;无 images → 空。
- `{mode:'custom', transform}`:transform 返回对象的 `images` 键 = 显式转发集(作者可从 `out.images` 挑选);返回纯字符串/无 images 键 → 不转发。
- 其余 mode(template/none/缺省 text)→ 不转发(空)。

**终点嵌图(embedFinalImages,仅当终点 NodeOutput.images 非空且 `embedFinalImages: 'markdown'`)**:

```
lines = 终点.images.map(img =>
    img.src ? `![工作流图片](${img.src})` : null   // 无 src → 跳过 + thinking 行提示
).filter(Boolean)
finalText = 终点.text + (lines.length ? "\n\n" + lines.join("\n\n") : "")
```

- src 为工作区**相对路径**(ctx.files.readImage 记录);pi-web 的 `replaceLocalMarkdownImages` 把它转 workspace preview URL 渲染(20 §9.7 已核实);TUI 显示为普通文本行(非目标,接受)。
- 路径安全性由读取时保证(写入时已校验);收尾不做二次校验。
- 终点文本会先经 30 §3 的 text_delta 流式映射——嵌图行在 `embedFinalImages` 之后才拼接,**流式期间用户看到的文本不含图行,done 消息的最终 text 块含图行**(与既有"最终文本纠偏"机制同款,30 §M4 纠偏逻辑复用)。

**占位与思考行的图片可见性**:

- 入口节点开始时 thinking 行:`收到 N 张图片`(N=0 省略)。
- 函数节点产出图片时 thinking 行:`—— 函数节点 collect:产出 2 张图片 ——`。
- 嵌图收尾时 thinking 行:`最终回答已附加 N 张图片(markdown 引用)`。

## 6. usage 记账(D15)

- 监听子会话 `message_end`(每个 assistant 消息):`usage` 增量累加到记账器。
- 键:`(hostSessionId, agentPath)`,`agentPath = flow:<flowName>#<nodeLabel> [> sub:<agentName> | subflow:<flowName>#<nodeLabel>]*`——subagent 链与 subflow(工作流引用)链可任意交错延伸(10 §6.1)。
- 函数节点不产生 usage(20 §2.2),不出现为 agentPath 条目(仅引擎 trail 有耗时)。
- 持久化:每次唤醒结束,`pi.appendEntry("pi-agents:usage", {wake, byPath: {…}})`(非模型上下文,session JSONL 自动保存;resume 后 `/agent-usage` 读取历史 entry 汇总)。
- 虚拟模型消息 usage/cost 恒 0(30 §5)——`/session` 统计不会重复计费;真实消耗只看 `/agent-usage`。

## 8. 中断与错误

- **Esc 中断(D16)**:宿主 abort → streamSimple 的 options.signal → 引擎 AbortController → 当前 Agent 节点的 session.abort() → 全链(subagent 工具正在跑的子会话同 signal);中断落在函数节点上则放弃其挂起 Promise(结果弃用,流程按 aborted 结束,见 §5)。收尾:流 push aborted error;池中 inherit session 已被 abort 污染(有半截对话)→ **保守起见该唤醒涉及的 inherit 节点全部弃池重建**(下次唤醒 fresh 语义,thinking 行提示)。
- **节点 Agent 抛错/子会话失败**:错误消息(含 agentPath、节点、原始错误)→ error 流。宿主 pi 对 error 有自动重试(用户可关);重试会**重新唤醒工作流**(streamSimple 重入)——inherit 池仍在,重试是从头再跑一遍工作流(入口节点重跑)。文档写明:重试 = 整个工作流重跑,不是断点续跑(非目标)。
- **子会话上下文超限**(§3.2):error 流,消息含节点名与建议。

## 9. 持久化与恢复(resume/fork)

pi 宿主 session 持久化(JSONL);子会话不持久化(in-memory)。恢复语义:

| 项                     | 恢复行为                                                                       |
| ---------------------- | ------------------------------------------------------------------------------ |
| 虚拟模型选中状态       | pi 原生(model_change entry);provider 未注册时回落最后物理模型(pi 原生行为)     |
| 占位工具激活           | `session_start(resume)` 扫分支最近 model_change:是本 provider → setActiveTools |
| inherit 节点池         | **不恢复**;下次唤醒按"首唤醒"重新创建空会话。thinking 行提示一次。             |
| /agent-usage 历史      | 从 entry 聚合,天然恢复                                                         |
| 世界书 persistent 条目 | 子会话重建后视为全新(trigger 重新评估;不追求跨进程去重,10 §5 已声明)           |

- fork(从历史分叉):同 resume;`session_tree` 事件时清空当前池(§3.2)。

## 10. 宿主上下文瘦身(`historyFootprint: "compact"`,设计预留)

- 钩子:本扩展在宿主注册 `context` 事件(仅当当前模型是本 provider 且配置为 compact):
    - 扫描 `event.messages` 中 `provider === "pi-workflows"` 的旧 assistant 消息(非最后一条);
    - 替换为单文本块摘要 user-可读消息(「[工作流 dev-loop 第 N 唤醒:<输出前 200 字>;工具调用 M 次]」);
    - 保留最后一条完整(供宿主模型引用上一轮)。
- 风险:改历史会让宿主 provider 的 prompt cache 失效(消息序列变了);compact 是明确的价格换上下文选项,缺省 off。
- 第一期交付 `full`;compact 实现放二期(30 §6 已声明)。

- 旧路径 `~/.pi/agent/pi-agents.json` / `<cwd>/.pi/pi-agents.json` 仍作为**最低优先级回退**读取,读到即发一次迁移告警(提示新路径),避免静默丢配置导致模型漂移。
- `model`/`thinkingLevel` 是解析链第 3 级(10 §3.1):仅在节点与 Agent 定义都未指定时生效;最终空缺 = pi 全局默认模型(settings 默认)。
- `images` 各字段 0/false 即关闭对应通道(函数节点返回 images → error 流,提示通道已关);`maxImageBytes` 同时约束唤醒图与 ctx.files.readImage。
- 该目录(含 `config.json`)由 `/agent-init` 一键创建(50 §1.1)。

## 12. 并发与重入

- 同一宿主 session 同一时刻只有一次唤醒(agent loop 串行),引擎无锁需求。
- 多宿主 session(多终端/多标签):各自 SessionPool 实例?**是**——池挂在扩展运行时的 per-session 状态上(pi 扩展运行时随 session 走),键里仍带 hostSessionId 防御性区分。
- 子会话内部工具并行:pi 原生行为(同一 assistant 消息的多工具并行),不干预;透传映射按事件到达顺序(30 §3 注明交错可能性由并行导致,占位调用顺序非严格串行)。

## 13. 事件发射(pi-web 插件数据源,D23)

扩展是插件数据的唯一真相;发射器(`src/extension/emit.ts`)消费装载与引擎事件,`pi.events.emit("pi-agents", frame)` 发给服务端插件(协议全帧定义见 70 §4;**帧内无图片数据、preview 截断 ≤200 字**)。

| 发射点                                  | 帧                          | 说明                                                     |
| --------------------------------------- | --------------------------- | -------------------------------------------------------- |
| 装载完成(session_start/reload 后)       | `catalog`                   | agents/flows 目录(name/title/description/来源)+ 装载警告 |
| 浏览器 `refresh-catalog` cmd 回流       | `catalog`(重发)             | 走 cmd 通道(70 §4.2)                                     |
| 引擎:节点进入/离开(runNode ± runFnNode) | `node-enter` / `node-exit`  | visit/durationMs/textPreview;**点运行图**                |
| 引擎:边选择完成                         | `edge`                      | from/to/via(含 maxIterations 触发);条件边真实走向        |
| spawn 工具开始/结束(10 §6 钩子)         | `spawn-start` / `spawn-end` | parentPath 按 agentPath 链,运行图徽章                    |
| 唤醒开始/结束(streamSimple 首尾)        | `wake-start` / `wake-end`   | wakeIndex/flow/inputPreview/终态;textPreview ≤200 字     |

- 发射失败被吞(pi.events 无订阅者时静默)——插件不在 = 零开销旁路,不阻塞引擎。
- 中断/错误唤醒同样发 `wake-end`(status: aborted/failed),面板如实显示。
